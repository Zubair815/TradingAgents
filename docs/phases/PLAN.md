# Sequential execution plan

This is the agreed scope and order recovered from this conversation. Historical audit claims and commit titles are not completion evidence. Each phase must independently pass inspection, targeted tests, `ruff check .`, `pytest -q`, diff review and a phase report before the next starts.

| Phase | Work | Completion gate | Spec sections |
|---|---|---|---|
| **0. Correct misleading behavior** | Remove the hard coded web LONG/BUY analysis result; return an explicit unavailable or failed state until the real pipeline is connected. Disable the graph’s default creation of “actual” trades from proposals. Label or disable the synthetic web backtest as a demo. Add regression tests for these cases. | No endpoint presents fabricated analysis or broker execution as real. | 1–4, 24, 30–32, 73–74, 107–110 |
| **1. Establish shared contracts and persistence** | Finalize `AnalysisRequest`, candle, quote, event, snapshot, proposal, risk decision, broker event, trade, and lesson schemas. Add migrations for analysis runs, immutable market snapshots, agent reports, and version links. Define IDs, UTC timestamps, provenance, and state transitions once. | Every later phase can read and write the same versioned records; migrations and integrity tests pass. | 4–9, 29–31, 50–54, 61–63, 91–92 |
| **2. Make market and event data trustworthy** | Implement MT5 price data as the live broker source, explicit Yahoo fallback metadata, closed candle alignment, and complete quality checks. Replace generated economic releases with sourced events carrying publication and revision times. Validate news provenance, deduplication, and historical availability. Fix daylight saving session calculations. | Bad or stale critical data blocks a tradeable proposal; historical queries reveal only information available at the cutoff. | 7–9, 12–16, 74, 93–96 |
| **3. Finish deterministic Forex calculations** | Complete indicator metadata, structure, volatility, pip value, account currency conversion, session, and regime outputs. Resolve rounding and precision defects. Put calculations in reusable services consumed by agents, risk, UI, and backtests. | Same input snapshot produces the same calculated values everywhere; precision and edge case tests pass. | 10–13, 25–28, 70, 101, 103 |
| **4. Complete risk and proposal rules** | Enforce spread, news blackout, RR, setup age, position size, margin, total account risk, correlation, exposure, and broker constraints. Make rejection produce `NO_TRADE` everywhere. Validate proposal schema and expiry before persistence. | Every approved proposal passes deterministic rules; rejected proposals cannot be displayed or recorded as actionable trades. | 23–32, 47–48 |
| **5. Connect the real research workflow** | Feed one immutable snapshot into technical, macro, and news analysts, debate, trader, and risk nodes. Make web and CLI call that graph and show actual node progress. Persist reports, decisions, model/prompt versions, and failures under one run ID. Parallelize independent analysts only after the data contract is stable. | A web or CLI analysis can be traced from request through sourced data to a stored `LONG`, `SHORT`, or `NO_TRADE` decision. No hard coded prices or progress events remain. | 1–4, 17–24, 79, 91–99, 107 |
| **6. Build authoritative MT5 observation** | Add a read only synchronization process for positions, orders, deals, commissions, swaps, SL/TP changes, partial closes, and closures. Make imports idempotent by broker IDs. Reconcile proposals with evidence, and require review for uncertain matches. Test with synthetic MT5 records, then a demo terminal. | Repeated synchronization creates no duplicate trades or deals; journal state agrees with broker history. | 32–41, 78, 102–103, 108 |
| **7. Complete journal and performance accounting** | Derive net P/L, R, MFE/MAE, exit quality, skipped and expired proposal outcomes, theoretical versus actual results, segmentation, expectancy, drawdown, and confidence calibration from authoritative records. Keep calculations separate from AI interpretation. | Metrics reconcile to known synthetic trade histories and can be recomputed from stored events. | 42–60, 81, 84–86 |
| **8. Build evidence guarded learning** | Generate structured reflections from completed trade records, attach supporting evidence, rank lessons by pair/setup/session/regime, require minimum sample strength, and decay stale lessons. Record whether a lesson influenced a later proposal. | A single trade cannot become a “proven” rule; future analysis can explain which lessons it used and why. | 64–72 |
| **9. Make backtesting valid and comparable** | Fix candle timing so decisions made at a close fill no earlier than the next eligible price. Replay the production strategy and risk rules with historical snapshots, calendar/news availability, spreads, commission, swap, slippage, and ambiguous fills. Add walk forward and out of sample evaluation, then demo forward comparison. Keep the existing investment backtester separate. | Point in time tests catch future data and same candle fill leakage; reported results identify estimated costs and ambiguous exits. | 73–78, 100–103, 109 |
| **10. Finish the user interface** | Build the Forex dashboard, analysis form and progress, proposal card, manual decision flow, open trades, journal, performance, learning, backtest, settings, and health views on top of the completed APIs. Add the guided CLI flow. | A user can follow the complete workflow without using raw API calls; displayed values match database records. | 79–87 |
| **11. Harden operation and release** | Finish configuration validation, secret redaction, structured logging, error taxonomy, retries, cache policy, health checks, backups and restore tests. Clear Ruff findings, resolve skipped relevant tests, and run unit, integration, end to end, MT5 demo, and full regression suites. Version experimental features and define promotion criteria. | Clean quality gates, successful backup restore, repeatable demo run, and documented remaining external dependencies. | 88–106, 109–110 |
